the "tickets before code" principle is a hint at a more important principle, we have not yet documented. it is so important, we should not only manifest it in the instructions, but also show it in our presentation deck, as it is the core cycle in our production workflow. The cycle is incremental and iterative, but each cycle is designed to gather measurable evidence from the system and the user to optimize the system performance. An important part of the cycle is understanding what the user wants and what the most favorable way to the goal is, the other important part is the operational efficiency of the implementation and the correctness of the executable measurements testing the implementation. A closed loop system is always required to return to the user with a response to their request. The quality of the response for the user is equal to the quality of the implementation and his satisfaction with the result.
