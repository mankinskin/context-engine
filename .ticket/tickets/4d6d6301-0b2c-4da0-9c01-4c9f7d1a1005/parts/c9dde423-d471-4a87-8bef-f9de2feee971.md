## Objective

Adapt the existing install-validation Docker harness into a workflow-tools minimal-consumer scenario. The container must clone `workflow-minimal-demo`, invoke the commit-pinned public installer, configure `install-ctl`, verify the selected installed artifacts, build the consumer, execute a ticket/spec operation, and read back the consumer stores.

## Done Condition

- The Docker harness runs the documented public tutorial rather than context-engine source-build viewer checks.
- Failures retain diagnostics.
- The scenario is suitable for GitHub Actions on pull requests and main.

## Validation

Build and run the Docker image locally; assert installed binaries below `<installation-home>/.workflow-tools/bin/` and read back ticket/spec records from the consumer store.
