## Docker Installation Validation — Implemented and Passing

Built `workflow-tools/install/docker-validation/` (`Dockerfile`, `run-in-container.sh`, `run-docker-validation.sh`), adapted from the pre-existing context-engine `tools/install-validation/Dockerfile.viewer` pattern but targeting the actual public minimal-consumer flow instead of a context-engine source build:

- Fresh image, `git clone --depth 1` of `workflow-minimal-demo` from GitHub (no local monorepo path).
- Installs `install-ctl` via `install.sh` (ticket `c2e341a1`, already done) into an isolated root; asserts the binary exists and runs.
- Runs the consumer's own `run-tutorial.sh` against `bootstrap.sh` (COPYed build context, not yet curl-fetched — see caveat below), which installs pinned `ticket`/`spec` CLIs, initializes the consumer's store, creates a ticket, builds the demo, and reads the ticket back.
- Verifies the ticket store lands under `<workspace>/.workflow-tools/ticket` (or legacy `.ticket`), and asserts at least one record round-trips through JSON output.

**Real end-to-end runs (not simulated) surfaced and fixed 3 genuine bugs**, none of which were caught by prior manual/local validation because the local `workflow-minimal-demo` checkout already had leftover initialized stores from earlier manual runs, masking a truly-fresh-clone failure:

1. `workflow-minimal-demo`'s pinned `ticket` rev (`bd826dc9`) was stale relative to what `bootstrap.sh` should use; bumped both to the currently-published `ticket`@`a02cb0773` / `spec`@`6dddad9d` and regenerated `Cargo.lock`.
2. The demo (`src/main.rs`) hardcoded `TicketStore::open(workspace.join(".ticket"))` (legacy-only), but `ticket init` actually produces the canonical `.workflow-tools/ticket` layout — the two layout assumptions never matched in a genuinely fresh workspace. Fixed to try canonical first, legacy as fallback.
3. The harness's own record-count check used a JSON regex that didn't tolerate `serde_json::to_string_pretty`'s space after `:` — fixed the extraction pattern.

Both `workflow-minimal-demo` fixes were committed and pushed (`1de6301`, `2b95047`) since the harness clones from GitHub and needed the real fix published, not just a local working-tree change.

Validation passed (run twice for reproducibility, exit 0 both times):
