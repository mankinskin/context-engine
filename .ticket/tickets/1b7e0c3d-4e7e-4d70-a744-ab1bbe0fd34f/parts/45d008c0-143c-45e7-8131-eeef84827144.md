## Status

RESOLVED — `InteroperableArtifact` lives in `memory-kernel`.

The rule was: test/validation-specific → `test-api`; generally relevant to all memory tools → `memory-kernel`. It resolves to `memory-kernel`.

## Evidence

- The two definitions are API-identical: both declare exactly `fn artifact_class(&self) -> &'static str` and a defaulted `fn interoperability_gaps(&self) -> Vec<&'static str> { Vec::new() }`. No associated types, no extra methods. Only the doc wording differs.
- The kernel version carries no test/validation vocabulary. The `test-api` version mentions `"validation-execution"` and "dynamic validation checks" only in doc comments, never in method names, associated types, or required semantics.
- The current ownership boundary is inverted: `log-api`'s `RuntimeLogSession` and `ValidationLogCapture` implement the `test-api` trait despite not being test artifacts.
- The kernel needs the trait at its own persistence boundary: `MoveJournal` implements it and `persist_journal` statically requires it, rejecting a journal that reports gaps before writing.

Implementors today: `MoveJournal` (memory-kernel, kernel trait); `MoveJournal` (legacy memory-api, test-api trait); `ValidationExecution`, `BenchmarkExecution` (test-api); `ValidationLogCapture`, `RuntimeLogSession` (log-api). No `dyn InteroperableArtifact` usage exists — only three compile-time generic bounds.

## Merge shape

Keep the kernel definition and its root re-export unchanged:

```rust
pub trait InteroperableArtifact {
    fn artifact_class(&self) -> &'static str;
    fn interoperability_gaps(&self) -> Vec<&'static str> { Vec::new() }
}
```

Absorb no methods from `test-api` — both are already identical. Then: `test-api` depends on `memory-kernel`, deletes its local definition, and adds `pub use memory_kernel::InteroperableArtifact;` for compatibility; `test-api`'s `TraceableArtifact` extends the kernel trait; `log-api`'s implementations migrate to the kernel trait; the legacy `memory-api` copy is deleted during this ticket's cutover.

## Risk

Split trait identity during a partial migration — any remaining `test_api::InteroperableArtifact` impl or bound becomes incompatible with the kernel trait despite the identical method set. The change must land atomically across `test-api`, `log-api`, and the legacy crate deletion.
