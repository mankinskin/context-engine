## Objective
Create one canonical, maintainable registry of every repository-delivered executable and hook. Generate a human-readable Markdown command catalog from the registry. The catalog is the command-selection source for Terminal Command Agent; install-ctl owns installation and lifecycle actions for registry entries.

## Scope
- Register Cargo binary targets, executable scripts, managed services, extensions, and hooks with stable ids, invocation metadata, ownership, lifecycle capability, and safety classification.
- Generate a committed Markdown catalog from the registry and validate catalog freshness in CI or repository checks.
- Extend install-ctl to list, install, uninstall, start, restart, and stop registry-managed tools and services where the entry declares that capability.
- Make Terminal Command Agent load and plan from the generated catalog while retaining its explicit user approval gate for non-safe commands.
- Include repository hooks in the registry, initially as discoverable or installable entries; external tools remain out of scope.

## Done
All command-facing artifacts are registered, the generated catalog is current and human-readable, install-ctl lifecycle operations are registry-driven, and Terminal Command Agent uses the catalog for one-command planning and user-gated execution.
