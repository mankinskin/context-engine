# Build fs-api: token-bounded filesystem operations (api + cli + mcp)

**Crate names**: `fs-api` (api crate); `fs-cli` (CLI transport); `fs-mcp` (MCP transport).

**Implementation note**: This is a **net-new implementation**. The precedent ticket `bd5e9aee` extracted an already-existing `compact-terminal-mcp` into layered api/cli/mcp crates. There is no existing filesystem abstraction in the workspace today. What transfers from that precedent is **only** the three-crate layout and workspace wiring pattern — not any logic. This ticket builds a new capability from scratch.

Parent epic: `.ticket/tickets/e342cc4c-a7a4-42de-81fc-572d0497d12b` (244c3113 Filesystem Ops)  
Spec: `agent-tooling/filesystem-operations` (`.spec/specs/58a1d32c-2643-455c-bf3b-e0ccf9f`)

## Problem

No `*-filesystem*` tool exists under `memory-api/tools/mcp/` or `memory-api/tools/cli/`. Listing, stat, move, copy, and delete are done through raw shell, which returns unbounded output, has no shared conflict model, and offers no preflight for destructive operations — unlike the entity stores, which already have `*_move_preflight` / `*_move_apply` / `*_move_rollback` families.

## Work

Build fs-api from scratch with:

1. Create `memory-api/crates/fs-api/` owning listing, stat, and mutation, with transport-independent request/response types and one error model (precedent: `compact-terminal-api`, `peek-api`).
2. Bounded listing with explicit depth and entry caps plus explicit truncation reporting (precedent: `peek-api` InspectMode, `compact-terminal-api` RunResult::Spilled).
3. Include/exclude glob filters and workspace ignore-rule honoring using the `ignore` crate's `WalkBuilder` (precedent: `audit-api/src/index.rs`).
4. Metadata-only `stat` that never returns content (fields: exists, kind, size, modified time).
5. Move, rename, copy, and delete with destination-conflict detection and an explicit overwrite opt-in.
6. Bounded mutation responses listing only affected paths and conflicts (no full tree dumps).
7. Add thin `memory-api/tools/cli/fs-cli/` and `memory-api/tools/mcp/fs-mcp/` transports (precedent: `compact-terminal-cli`, `compact-terminal-mcp`).
8. Register the MCP server in `.vscode/mcp.json` and `.github/mcp.json` as `fs-mcp` with cost-gate wrapping (precedent: existing entries for `peek-mcp`, `compact-terminal-mcp`).
9. Add `'fs-mcp/*'` to the `tools:` wildcard lists in `.agents/agents/*.agent.md` templates where filesystem operations are relevant (default, implement, explore, research, etc.).

## Acceptance Criteria

- [ ] `fs-api` crate created with transport-independent request/response types and one error enum (no separate cli/mcp error types).
- [ ] `list_dir(path, depth_limit, entry_limit, include_globs, exclude_globs, honor_ignore)` returns bounded results with a `truncated: bool` flag and `total_found: Option<usize>` when truncation occurs.
- [ ] `WalkBuilder` from the `ignore` crate is used for traversal and respects `.gitignore`, `.ignore`, and similar ignore files.
- [ ] `stat(path)` returns metadata (exists, kind [file/dir/symlink], size, modified time) without reading file content.
- [ ] `move_file(src, dest, overwrite)`, `rename_file(old, new)`, `copy_file(src, dest, overwrite)`, `delete_file(path)`, and `delete_dir(path, recursive)` all return structured conflict/success results with explicit `ConflictKind` enum (e.g., `DestinationExists`, `SourceMissing`, `PermissionDenied`).
- [ ] Mutation responses are bounded: return only `affected_paths: Vec<PathBuf>` and `conflicts: Vec<Conflict>`, not full tree state.
- [ ] `fs-cli` binary delegates to `fs-api` with no reimplemented traversal logic; accepts `--depth`, `--limit`, `--include`, `--exclude`, `--honor-ignore`, `--overwrite` flags.
- [ ] `fs-mcp` server exposes tools matching the api surface (e.g., `fs_list_dir`, `fs_stat`, `fs_move_file`, etc.) with JSON request/response matching api types.
- [ ] MCP server registered in `.vscode/mcp.json` and `.github/mcp.json` with `mcp-cost-gate` wrapper following the existing pattern.
- [ ] `'fs-mcp/*'` added to `tools:` lists in `.agents/agents/default.agent.md`, `.agents/agents/implement.agent.md`, `.agents/agents/explore.agent.md`, `.agents/agents/research.agent.md`, and any other relevant agent templates.
- [ ] `cargo test -p fs-api` passes with focused cases:
  - Depth-capped listing on nested tree returns truncation flag and stops at limit.
  - Entry-capped listing on flat dir returns truncation flag when entry count exceeds limit.
  - Include/exclude filters correctly match patterns (test both).
  - Ignore-rule honoring excludes `.gitignore`-listed paths.
  - Stat on missing path returns structured error, not panic.
  - Move onto existing destination without `overwrite=true` returns conflict.
  - Move with `overwrite=true` succeeds and reports overwritten path.
  - Delete of missing path returns structured error (not panic or silent success).
  - Response size for large directory mutation is bounded (no full tree dump).
- [ ] `cargo test -p fs-mcp` passes (integration: JSON request → api call → JSON response).
