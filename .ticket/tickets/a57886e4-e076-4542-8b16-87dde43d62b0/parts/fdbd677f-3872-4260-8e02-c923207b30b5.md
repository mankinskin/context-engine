## Implementation plan: doc extraction and viewer migration

### Established baseline
`memory-api/crates/memory-api` is deleted. `doc` commits `memory_kernel = { git = "https://github.com/mankinskin/memory-kernel", branch = "main" }`; a relative path is allowed only in a root `[patch]` development override. Ticket `1b7e0c3d` proved patch-free remote resolution.

Create public crate `doc` re-exporting `doc-api`, with empty defaults and a feature-gated `doc-http` bin built on `transport-harness` from `memory-kernel`. The ticket pilot in `26da8f59` establishes the single-crate shape. Keep document-domain typed manifest accessors, if present, as `doc-api` extension traits preserving existing `extra` keys; do not put doc types in the kernel.

### Verified source surface
- API: `memory-api/crates/doc-api`.
- Legacy transport to consolidate first: `memory-api/tools/http/doc-http`.
- Viewer and frontend: `memory-viewers/doc-viewer`, including `frontend` and `e2e`.
- No `doc-cli` or `doc-mcp` crate exists today; do not invent a legacy migration source.

### Consumers to repoint
Only `memory-api/tools/http/doc-http` currently consumes `doc-api`; the viewer uses the doc HTTP surface rather than a direct API dependency.

### Execution
1. Fold `doc-http` into feature-gated `doc-http` in public crate `doc`, preserving routes and integration tests.
2. Move `doc-api`, public crate `doc`, and `doc-viewer` to the standalone doc repository while preserving the viewer-to-HTTP boundary.
3. Repoint root membership and deploy/install configuration; remove the monorepo paths after the viewer and HTTP transport compile externally.

### Acceptance criteria
```bash
cargo test -p doc-api -p doc-http
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
cd memory-viewers/doc-viewer/e2e && npm test
```
Validate the doc viewer in an external fullscreen Chromium-family browser and capture Playwright screenshots. `AGENTS.md` requires browser verification plus the local Playwright wrapper E2E.

### Risk
Standalone proof depends on the published `memory-kernel` git dependency. The viewer must not retain an accidental monorepo path dependency after relocation.
