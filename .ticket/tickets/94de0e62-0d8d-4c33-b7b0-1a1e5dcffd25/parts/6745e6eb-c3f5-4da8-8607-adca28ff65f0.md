## Implementation plan: session extraction

### Established baseline
The legacy `memory-api/crates/memory-api` crate is deleted. Use `memory_kernel` from `https://github.com/mankinskin/memory-kernel` branch `main` as a committed git dependency; local paths are root `[patch]` overrides only. Ticket `1b7e0c3d` established the patch-free build.

Create public crate `session` re-exporting `session-api`, with an empty default feature set and feature-gated `session` and `session-mcp` bins built on `transport-harness` from `memory-kernel`, mirroring ticket `26da8f59`. Implement session-domain typed manifest accessors in `session-api` extension traits with byte-compatible `extra` keys; do not leak session types into the kernel.

### Verified source surface
- API: `memory-api/crates/session-api`.
- Legacy transports to consolidate first: `memory-api/tools/cli/session-cli`, `memory-api/tools/mcp/session-mcp`.
- No `session-http` or viewer exists.

### Consumers to repoint
`memory-api/crates/session-workspace-resolver`, `memory-api/crates/audit-api`, `memory-api/crates/memory-matrix`, `memory-api/crates/session-capture-hook`, `memory-api/tools/mcp/mcp-toolmon`, and `memory-api/tools/cli/audit-cli` consume `session-api` outside session's own transports.

### Execution
1. Consolidate `session-cli` and `session-mcp` into public crate `session`, preserving binary names and current tests.
2. Move `session-api` and the consolidated crate to the session repository, then repoint every listed consumer to its git URL.
3. Remove old monorepo paths only after consumers compile against the published session repository.
4. Extract after `feedback`, `test`, `rule`, and `spec`: `session-api` consumes all four (and ticket).

### Acceptance criteria
```bash
cargo test -p session-api -p session-cli -p session-mcp
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
```

### Risk
A standalone proof must wait for the published `memory-kernel` and sibling APIs `feedback`, `test`, `rule`, and `spec`; committed relative paths are forbidden.
