## Resolved Decisions

1. The legend is inside the graph: every ticket graph uses a single Mermaid fenced code block containing a `subgraph Legend` block. The legend is never a separate diagram or prose beside the graph.

2. Edge classes have opposite directions and distinct styles. Stored `depends_on` dependency edges render as solid arrows, `A --> B`, meaning "A is blocked by B" and pointing at the prerequisite. Derived execution-order edges render as dashed arrows, `A -.-> B`, meaning "A runs before B". For a given ticket pair, the two classes point in opposite directions. The embedded legend states those meanings in words. A diagram may contain both classes, and every class present appears in the embedded legend.

3. Each node label uses `<b>{type} · {short-id}</b><br/>{wrapped title}`. Ticket types use `classDef` colour coding for `task`, `feature`, `bug`, and `external`. The Legend subgraph includes one sample node for every type used by the diagram.

4. A rendered graph is acceptable only when copying its one Mermaid code block into an empty document reproduces the complete meaning, including the legend.

The arrow-direction question is resolved: stored dependency and derived execution-order edges are both rendered with distinct styles and opposite directions.
