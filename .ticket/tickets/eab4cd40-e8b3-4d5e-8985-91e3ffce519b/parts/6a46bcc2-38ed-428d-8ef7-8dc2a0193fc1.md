## Implementation plan: test extraction

### Established baseline
The former `memory-api/crates/memory-api` base crate is deleted. Commit `memory_kernel` as the `https://github.com/mankinskin/memory-kernel` git dependency on branch `main`; keep relative paths in a root `[patch]` only. Ticket `1b7e0c3d` proved remote resolution without a patch.

Create public crate `test` re-exporting `test-api`, with no default features and feature-gated bare `test` and `test-mcp` bins using `transport-harness` from `memory-kernel`, following ticket `26da8f59`. Keep test-specific typed `EntityManifest` accessors in `test-api` extension traits with byte-compatible `extra` keys, never in the kernel.

### Verified source surface
- API: `memory-api/crates/test-api`.
- Legacy transports to consolidate first: `memory-api/tools/cli/test-cli`, `memory-api/tools/mcp/test-mcp`.
- No `test-http` or viewer exists.

### Consumers to repoint
`context-stack/context-api`, `context-stack/context-insert`, `context-stack/context-read`, `context-stack/context-search`, `context-stack/context-trace`, `memory-api/crates/log-api`, `memory-api/crates/memory-matrix`, `memory-api/crates/session-api`, and `memory-api/crates/spec-api` consume `test-api` outside test's own transports.

### Execution
1. Consolidate `test-cli` and `test-mcp` into public crate `test`, retaining `test` and `test-mcp` names and existing tests.
2. Before extraction, separate the legacy `test-cli -> log-api` dependency from the public `test-api -> log-api` boundary: `log-api` consumes `test-api`, while `test-cli` consumes `log-api`. Preserve a one-way published dependency graph rather than creating a `test <-> log` git cycle.
3. Move `test-api` and public crate `test` to the standalone repository and repoint every listed consumer.
4. Publish test before `spec`, `session`, and `log` because all consume `test-api`.

### Acceptance criteria
```bash
cargo test -p test-api -p test-cli -p test-mcp
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
```

### Risk
The `test-cli`/`log-api` versus `log-api`/`test-api` relationship is an ordering hazard that must be broken at the transport boundary before standalone repositories can build. Published `memory-kernel` and `log` availability are also required for final proof.
