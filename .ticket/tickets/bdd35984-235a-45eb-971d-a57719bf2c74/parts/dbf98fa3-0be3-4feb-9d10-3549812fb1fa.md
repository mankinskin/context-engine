## Implementation plan: feedback extraction

### Established baseline
`memory-api/crates/memory-api` is deleted. `feedback` must use `memory_kernel` through `memory-kernel`'s git URL on `main`; a relative path may appear only in the root development `[patch]`, never in committed dependency metadata. Ticket `1b7e0c3d` proved the patch-free remote build.

Create public crate `feedback` re-exporting `feedback-api`, with empty defaults and feature-gated `feedback`, `feedback-mcp`, and `feedback-http` bins on `transport-harness` from `memory-kernel`, using the ticket-pilot consolidation pattern in ticket `26da8f59`. Keep feedback-domain typed manifest accessors, if present, as `feedback-api` extension traits using unchanged `extra` keys.

### Verified source surface
- API: `memory-api/crates/feedback-api`.
- Legacy transports to consolidate first: `memory-api/tools/cli/feedback-cli`, `memory-api/tools/mcp/feedback-mcp`, `memory-api/tools/http/feedback-http`.
- No viewer exists.

### Consumers to repoint
`memory-api/tools/cli/rule-cli`, `memory-api/crates/ticket-api`, `memory-api/crates/rule-api`, `memory-api/crates/session-api`, and `memory-api/crates/spec-api` consume `feedback-api` outside feedback's own transports.

### Execution
1. Fold the three transport crates into feature-gated bins of public crate `feedback`, preserving bare `feedback`, `feedback-mcp`, and `feedback-http` names.
2. Move `feedback-api` and public crate `feedback` to the standalone feedback repository.
3. Repoint all listed consumers to the published git dependency, then remove legacy workspace members.
4. Publish feedback before `rule`, `spec`, and `session`, which all consume `feedback-api`.

### Acceptance criteria
```bash
cargo test -p feedback-api -p feedback-cli -p feedback-mcp -p feedback-http
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
```

### Risk
Standalone proof waits only on published `memory-kernel`, but feedback publication is a prerequisite for several sibling tool extractions.
