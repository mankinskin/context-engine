## Problem

A rolled-back provisioning attempt left `core.worktree = ../../../../../.worktrees/5cd0b38e-session/memory-api` in shared `.git/modules/memory-api/config` and stale linked-worktree registrations pointing at removed `044bb46a-session` and `5cd0b38e-session` directories. The main checkout then failed `git status` with `fatal: cannot chdir`, `git worktree prune` could not recover, and `worktree.sh new` could not create any worktree.

## Acceptance Criteria

1. A failed provisioning rollback restores every affected `.git/modules/<submodule>/config` file to its pre-attempt state, including removal of any `core.worktree` path pointing at a removed directory.
2. Rollback removes every linked-worktree registration created for submodules during the failed attempt.
3. A regression test simulates failed submodule-population bootstrap, then asserts that the main checkout `git status` succeeds.
4. The regression test asserts no stale submodule registration or removed-directory `core.worktree` value remains after rollback.
5. `worktree.sh doctor` detects and reports stale linked-worktree registrations and invalid shared `core.worktree` configuration.
6. The repaired rollback path allows a subsequent worktree bootstrap to succeed.

The defect blocks all new worktree creation and must preserve main-checkout usability even when bootstrap fails.
