# Execute and terminal capability matrix

| Surface | Input | Output | Lifetime | Follow-up input | Resume ID | CWD/env | Timeout/failure |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `context-mcp execute` | Structured `context_api::Command` | Domain command result | One command | No terminal input | Workspace name only | Domain workspace | Domain command error |
| `compact-terminal-mcp run` | Arbitrary shell `command`, optional `cwd` | Inline output or spill path | Single-shot child process | No: child stdin is `Stdio::null()` | None | Per-call cwd only | Timeout kills and reaps child; partial stdout retained |
| `compact-terminal-mcp read_spill` | Spill path and bounded range/grep | Bounded stored output | Follow-up read only | No | Spill path only | Not applicable | Missing/invalid spill error |
| `compact-terminal` CLI | Same run/read-spill model | Same result model | Single-shot | No | Spill path only | Per-call cwd only | Same API timeout behavior |
| VS Code integrated terminal | Human keystrokes via UI | Terminal output data event | Persistent UI terminal | Human only | VS Code terminal identity | Terminal-owned cwd/env | Close event / host lifecycle |

## Findings

- `compact-terminal` is deliberately one-shot. Its MCP `run` accepts an agent
  command and therefore cannot be an observer-only capability.
- `stdin=Stdio::null()` prevents the terminal server from consuming MCP stdin
  and ensures `compact-terminal` cannot accept follow-up input.
- No existing MCP surface exposes a persistent terminal handle, output cursor,
  terminal attachment, or observer-only access control.
- ticket-vscode targets VS Code `^1.90.0`; the extension host can use
  `window.onDidWriteTerminalData` for output from a selected integrated terminal.
  The listener sees process-written output, not human keystrokes.

## Recommendation

Implement a new session-oriented observer terminal rather than extending
`compact-terminal`:

1. `session-api` persists a session-bound terminal manifest and append-only
   output events.
2. `session-cli` and `session-mcp` offer only create, status, bounded peek, and
   close operations. They contain no input or execute verb.
3. ticket-vscode opens the integrated terminal from an explicit human command,
   filters `onDidWriteTerminalData` to that terminal, and appends output events.
4. A host without the terminal-data capability reports capture unavailable;
   it does not simulate or claim observation.

The chosen implementation is ticket `ea52bd6f-aa48-43f5-9228-0bff7190abf8`,
under spec `73dfa7f7-5fb4-4c75-a6b1-8773d8a1ca30`.
