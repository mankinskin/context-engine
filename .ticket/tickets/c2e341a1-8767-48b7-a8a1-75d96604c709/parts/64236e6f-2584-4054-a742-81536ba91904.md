## install.sh Public Entry Point — Implemented and Validated

Authored `workflow-tools/install.sh`: a commit-pinned `curl | bash` entry point that installs `install-ctl` (via `cargo install --git https://github.com/mankinskin/workflow-tools --rev <pinned>`) into a caller-supplied `--root` directory only, with `--dry-run` and `-- <install-ctl args>` passthrough. Documented in `workflow-tools/README.md` next to the existing `bootstrap.sh` section.

Real end-to-end validation (not simulated) surfaced and fixed a major, repo-wide blocker: 10 of 12 workflow-tools submodules (`doc`, `feedback`, `interview`, `log`, `peek`, `rule`, `spec`, `test`, `ticket`, and `audit`) were pinned in the superproject index to commits that existed locally but were never pushed to their public GitHub remotes — `cargo install --git` therefore could not resolve the workflow-tools workspace at all. Only `memory-kernel` and `session` were already correctly published. Audited all 12 submodules, then fast-forward-pushed the 10 missing pinned commits to their respective `origin/main` (no rewrites, no force-push).

Validation passed:

- `bash -n install.sh` — syntax check passed.
- `bash install.sh --dry-run --root <dir>` — previews the exact pinned `cargo install` command.
- `bash install.sh --root /tmp/wf-install-test` — real install against a scratch directory: compiles and installs `install-ctl.exe` from the pinned public commit with no local patches.
- `/tmp/wf-install-test/bin/install-ctl.exe --help` — installed binary runs correctly.

This closes a load-bearing gap for the whole extraction epic (`69eb4118`), not just this ticket: every other domain's `cargo install --git`/`[patch]`-free resolution claim depended on these pushes.
