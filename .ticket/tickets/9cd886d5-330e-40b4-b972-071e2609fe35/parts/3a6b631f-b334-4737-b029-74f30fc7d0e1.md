## Problem
A corpus-wide audit found ZERO files under `.agents/instructions/orchestration/**` declare `applyTo` frontmatter (~11+ files). Per `.agents/instructions/README.md`, omitting `applyTo` makes a file description-gated (surfaced on demand only); `applyTo: "**"` is the always-on form. Today every orchestration rule — general or narrow — is description-gated, so there is no way to guarantee a short set of general rules are always active while everything else stays scoped to relevant file domains.

## Scope (rescoped 2026-07-31, split out of the original ticket)
This ticket covers ONLY the near-term, hand-maintained, static convention:
- Define an `applyTo`-class scheme and apply it across `.agents/instructions/**`.
- A small set of SHORT, GENERAL orchestration rules get `applyTo: "**"` (always-on, corpus-wide). These must stay short and general — not a dumping ground for domain specifics.
- All other guidance files become specialized per file domain via domain-scoped `applyTo` globs (e.g. `**/*.md`, `**/*.toml`, `**/*.json`, `**/*.rs`) instead of being left purely description-gated.
- Includes fixing `.agents/instructions/orchestration/entity-disambiguation.instructions.md` specifically — this is what satisfies ticket 95403a71's reopened acceptance criterion 3 (verify the rule is scoped so agent modes beyond Interview Agent pick it up).

## Explicitly out of scope
- Any new frontmatter key beyond `applyTo` (no tags, no priority weights, no custom scoping keys).
- Any runtime/tooling-driven dynamic selection (e.g. selecting guidance by ticket domain tag at dispatch time). That is deferred to a separate future ticket that depends on rule-api deployment.

## Acceptance criteria
- A written `applyTo`-class convention exists (e.g. as a section in `.agents/instructions/README.md` or equivalent) naming: which files qualify for `applyTo: "**"`, and the domain-glob pattern used for specialized files.
- Every file under `.agents/instructions/orchestration/**` has non-empty `applyTo` frontmatter: either `"**"` for the always-on general set, or a domain-scoped glob for specialized files. Verify with a repo-wide grep confirming no file in that directory is missing `applyTo`.
- `.agents/instructions/orchestration/entity-disambiguation.instructions.md` specifically has `applyTo` frontmatter set (not `"**"` unless it qualifies as short/general per the convention above), closing ticket 95403a71's acceptance criterion 3.
- No file touched by this ticket gains any frontmatter key other than `applyTo`.
