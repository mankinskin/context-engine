## Implementation plan: audit extraction

### Established baseline
The legacy base crate `memory-api/crates/memory-api` is deleted. Commit `memory_kernel` from `https://github.com/mankinskin/memory-kernel` branch `main`; use relative paths only in a root `[patch]` development override. Ticket `1b7e0c3d` established remote patch-free resolution.

Create public crate `audit` re-exporting `audit-api`, with empty defaults and feature-gated bare `audit` and `audit-mcp` bins using `transport-harness` from `memory-kernel`, following the ticket pilot consolidation in ticket `26da8f59`. Move audit-specific typed `EntityManifest` accessors, if present, into `audit-api` extension traits with unchanged `extra` keys; keep the kernel neutral.

### Verified source surface
- API: `memory-api/crates/audit-api`.
- Legacy transports to consolidate first: `memory-api/tools/cli/audit-cli`, `memory-api/tools/mcp/audit-mcp`.
- No `audit-http` or viewer exists.

### Consumers to repoint
`memory-api/crates/memory-matrix` consumes `audit-api` outside audit's own transports.

### Execution
1. Consolidate `audit-cli` and `audit-mcp` into feature-gated `audit` and `audit-mcp` bins, retaining their tests and command behavior.
2. Move `audit-api` and public crate `audit` to the standalone audit repository.
3. Repoint `memory-matrix` and all workspace references to the published git dependency before deleting old paths.
4. Extract after `spec`, `session`, and `rule`, because `audit-api` currently consumes their APIs.

### Acceptance criteria
```bash
cargo test -p audit-api -p audit-cli -p audit-mcp
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
```

### Risk
Standalone validation requires published `memory-kernel` plus the sibling APIs consumed by audit. Do not mask missing publications with committed local paths.
