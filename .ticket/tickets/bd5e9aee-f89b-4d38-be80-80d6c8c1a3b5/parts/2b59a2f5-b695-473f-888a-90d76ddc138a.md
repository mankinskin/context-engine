# Extract `compact-terminal-api` and add a CLI transport

Parent epic: `.ticket/tickets/e342cc4c-a7a4-42de-81fc-572d0497d12b`
Spec: `agent-tooling/compact-terminal` (`63c60c9d-adbe-4ddb-8c1d-6156610d0753`)

## Problem

`memory-api/tools/mcp/compact-terminal-mcp` implements the bounded
command-execution contract (`run` + `read_spill`) but exists only as an MCP
transport. There is no `compact-terminal-api` crate and no CLI fallback, so the
spill/preview behavior cannot be reused or tested independently of MCP and
diverges from the `*-api` behavior + thin `*-cli`/`*-mcp` transport layering
established by `agent-tooling/peek-api`.

## Work

1. Create a `compact-terminal-api` crate owning command execution, the
   inline-vs-spilled decision, spill file lifecycle, and bounded spill reading,
   with transport-independent request/response types and one error model.
2. Reduce `compact-terminal-mcp` to a thin transport over that crate, preserving
   the current `run` and `read_spill` tool names and response shapes.
3. Add a `compact-terminal-cli` transport exposing the same operations for the
   documented MCP-unavailable fallback path.
4. Register the CLI in the workspace build and reference it from
   `.agents/instructions/orchestration/tool-output.instructions.md`.

## Acceptance

Mirrors the acceptance criteria of spec `agent-tooling/compact-terminal`.
Behavioral compatibility for existing MCP callers is required.
