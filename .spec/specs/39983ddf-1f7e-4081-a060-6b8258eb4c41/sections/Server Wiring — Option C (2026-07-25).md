The option-C client-layer enforcement is now wired at the MCP server declarations.

**Stdio cost-gate proxy** — [tools/model-prices/mcp_cost_gate_proxy.py](../../tools/model-prices/mcp_cost_gate_proxy.py) sits between the MCP client and each real server. It speaks the MCP stdio transport (newline-delimited JSON-RPC), reads the calling model from `CALLER_MODEL`, and for every `tools/call` asks the shared `cost_gate.evaluate()`. On `delegate` it short-circuits the call and returns a `tools/call` result with `isError: true` + delegation guidance — the real server never receives it. All other traffic passes through unchanged. Fail-open: unset `CALLER_MODEL` or missing price table ⇒ transparent passthrough (the client is the only un-spoofable source of model identity).

**Config wiring** — every server in [.vscode/mcp.json](../../.vscode/mcp.json) and [.github/mcp.json](../../.github/mcp.json) (11 servers each: context/ticket/spec/test/feedback/session/peek/rule/audit/compact-terminal/log-viewer) now launches `python mcp_cost_gate_proxy.py -- <real-command> [args]` instead of the bare command. `.vscode` supplies `CALLER_MODEL` via an `${input:callerModel}` prompt (default empty = passthrough); `.github` (Copilot CLI) inherits `CALLER_MODEL` from the process environment.

**Validation** — [tools/model-prices/test_mcp_cost_gate_proxy.py](../../tools/model-prices/test_mcp_cost_gate_proxy.py) (5 e2e tests, evidence `exec-vt-cost-gate-proxy-20260725`) plus a live check against the real ticket-mcp binary (opus-4-1 → `get_ticket_description` returns the delegation refusal). Cost-gate unit tests remain green (`exec-vt-cost-gate-20260725`).
